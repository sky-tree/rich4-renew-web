# 07 · 测试策略、验收标准与报告模板

## 1. 基本原则

每次功能性 PR 都至少测试规则、浏览器交互和构建中的受影响部分；修改渲染、资源、存档或联机时增加专项回归。缺乏资源或者缺少设备不能记为“通过”，只能记为“未执行/受阻”。

| 等级 | 规则 | 发布要求 |
| --- | --- | --- |
| P0 阻断 | 无法进入对局、崩溃/黑屏、存档损坏、非法公开素材、凭据泄露、联机规则分叉 | 必须修复或关闭对应能力 |
| P1 重要 | 多地图异常、明显功能回归、长帧/内存压力、回滚失败、移动端无法完成操作 | 首版修复或明确延期并隔离 |
| P2 改进 | 非关键动画细节、低频布局问题、图形质量可优化 | 建 Backlog，跟踪后续版本 |

## 2. 代码层测试

最低质量门：

```bash
cd game
npm ci
npm test
npx tsc --noEmit
RICH4_NO_ASSETS=1 npm run build
```

上述命令会验证规则测试与代码编译，但 `RICH4_NO_ASSETS=1` 不会保证完整图片/地图可用；完整网页测试必须在合法的实际资源环境运行。

现有 `core/*.test.ts` 已涉及地图、股票、卡片、八人、世界、大富豪结算、模拟和存档；改写其相关模块时应复用这些测试，不用截图回归代替逻辑测试。

## 3. 功能端到端场景

| 编号 | 用例 | 必须验证的现象 |
| --- | --- | --- |
| T-01 | 进入首页、菜单选项和新开局 | 首页/菜单有响应，音效与语言切换不黑屏 |
| T-02 | 普通模式 2–4 人 + AI | 掷骰、移动、转向、买地、支付、回合推进与结局正常 |
| T-03 | 股票、银行、卡片、工具、事件 | 弹框逻辑、金额、拥有者及特效前后状态一致 |
| T-04 | 多张原版地图 | 资源加载完整，人物和建筑不漂移，地图可缩放旋转 |
| T-05 | 自制/歌舞伎町地图 | 商店、特殊建筑、行人/车辆特效与触摸操作正常 |
| T-06 | 大富豪模式（五城十二人） | 世界状态、跨城、结算，且没有加载全部五城高清图 |
| T-07 | 手动和自动存档 | 同一浏览器刷新重进，恢复最近状态，自动档历史可选 |
| T-08 | 下载/分享图片 | 允许的浏览器分享成功；不支持则下载，不依赖 Capacitor |
| T-09 | 横竖屏切换/页面缩放 | UI 操作区可见，手指选中的目标与实际响应一致 |
| T-10 | 网络慢速、断开、404 | 显示加载进度、失败描述和重试，不能永久卡住 |
| T-11 | 缓存旧版后发布新版 | 不出现旧 manifest 对新文件的引用错误，历史存档可用 |
| T-12 | 派对（如启用） | 建房、加入、同步动作、断线恢复、超时托管，摘要不分叉 |
| T-13 | 老旧设备/低内存档 | 无浏览器进程被反复杀死、无解码死锁、低档资源降级正确 |
| T-14 | 全局卸载/重新载图 | 上一局事件监听、音频、Worker、纹理资源清理正确 |

### 视觉回归重点

对 Canvas 和未来 PixiJS 使用同一局面/相机参数进行截图对比，需人工核对：45°旋转投影、锚点、楼层遮挡、人物动作方向、地形拼缝、特效图层、控件点击命中、DPR 和清晰度。对动画场景选取固定帧或可重复的截图脚本，避免基于随机时序的像素阈值产生误报。

## 4. 浏览器/设备矩阵

| 平台 | 必测 | 关注点 |
| --- | --- | --- |
| Windows Chrome 最新稳定版 | 是 | Canvas/WebGL、字体、触摸/键鼠、保存 |
| Windows Edge 最新稳定版 | 是 | Chromium 差异、缩放和输入 |
| macOS Safari 最新稳定版 | 是 | Web Audio、图片解码、IndexedDB |
| Android Chrome 当前稳定版 | 是 | 触摸与横竖屏、低端机内存 |
| iPhone Safari 近期 iOS | 是 | 小屏布局、前后台恢复、配额 |
| iPad Safari（含较旧受支持版本） | 是 | 大屏、高 DPR、WebGL、资源错误提示 |
| Firefox 桌面 | 可选，纳入测试再承诺支持 | 浏览器 Web API 兼容差异 |

明确记录系统版本/浏览器具体版本、分辨率、DPR、可用内存档，不以“Safari 已测”代替设备信息。

## 5. 非功能目标

**先测基线再决定是否加严。** 初步推荐：

| 项目 | 初始目标/门槛 | 证据 |
| --- | --- | --- |
| 首页下载量 | 首次必须资源争取 ≤10 MiB；排除其他地图大资源 | Network HAR + 报告 |
| 桌面帧率 | 典型场景争取稳定 60 FPS | 3 轮重复 FPS/p95 |
| 手机帧率 | Low 30 FPS；Mid/High 30–60 FPS（目标，非保证） | 真机结果 |
| 资源一致性 | Manifest 引用的已发布资源 100% 有效 | 构建引用校验 + 线上 404 测试 |
| 存档 | 持续游玩后保存/恢复游戏状态不丢失 | 前后状态比较、异常注入 |
| 多人联机 | 正常条件下所有端规则摘要一致 | 预设脚本长局 + 断线恢复 |
| 升级与回滚 | 不破坏已有存档、不出现新旧包混读 | 升级/回退演练 |

对于视觉/性能目标，应在固定设备和场景的 Canvas 基线上进行**配对比较**；PixiJS 实验若没有可重复收益，可以拒绝迁移，而不因技术选型已写在计划里就强制上线。

## 6. 自动化与人工分工

- Vitest：游戏核心、RNG、存档版本转换、资源清单解析和 URL 重写的确定性测试。
- Playwright（计划引入）：本地 HTTP 服务、进入页面、检查脚本异常、截图、基本操作和 Network 404；需注意真正图片/声音依赖授权素材。
- 人工真机：iOS Safari 内存与后台恢复、移动触摸、声音首次点击限制、PWA 缓存、WebRTC TURN 联机。
- CI 产物：报告路径、日志、截图、版本、测试环境，禁止包含受限素材和凭据。
