# 03 · 里程碑、任务拆解与交付顺序

> 以下是待实施计划，时间以完成依赖和验收为准，不对未经开发的功能标记“已完成”。P0 为阻断项，P1 为首版重要项，P2 为后续优化项。每阶段可拆成多个独立 PR。

## 总览

| 阶段 | 优先级 | 核心产物 | 前置依赖 | 状态 |
| --- | --- | --- | --- | --- |
| M0 开发基线与合规闸门 | P0 | 跑通现有代码检查、清单、许可方案 | Fork 已完成 | 待开始 |
| M1 纯 Web 化 | P0 | 无 Capacitor/Electron 依赖的 Web 构建与浏览器可玩版本 | M0 | 待开始 |
| M2 网页资源分层 | P0/P1 | 资源报告、分包清单、缺失恢复、首屏轻量化 | M1 | 待开始 |
| M3 小范围 Web 测试发布 | P0 | 自动化验证、Nginx 测试站、回滚能力 | M1+M2+授权 | 待开始 |
| M4 PixiJS/WebGL 渲染实验 | P1 | 单地图对照、指标、是否迁移决策 | M2 基准 | 待开始 |
| M5 联机生产化与存档增强 | P1/P2 | 可控信令/TURN、存档迁移与备份 | M3 | 待开始 |
| M6 PWA 与公网规模优化 | P2 | 可选离线包、CDN、监控与扩展 | M3，视需求 | 待开始 |

## M0 · 基线、依赖、授权与风险

- [ ] M0-01 记录仓库 HEAD、Node/npm 版本、lockfile 状态、上游远端。
- [ ] M0-02 `npm ci` 后运行 `npm test`、`npx tsc --noEmit`，归档失败记录；无素材时明确标记“测试受限”。
- [ ] M0-03 执行无资源构建（`RICH4_NO_ASSETS=1 npm run build`）确认 JS/CSS 可正常编译。
- [ ] M0-04 审计 `@capacitor/*`、Electron、原生路径和运行时平台分支；记录待移除表。
- [ ] M0-05 统计全资源体积与文件数量（如果有合法的本地素材），记录清单版本与磁盘空间。
- [ ] M0-06 决定素材发布授权策略；没有明确分发权时，只允许受控验证或已授权替代素材。
- [ ] M0-07 记录浏览器与设备的初始测试矩阵，建立缺陷列表。

**验收**：记录出可重复的基线命令、测试结果、阻断项；后续性能比较有原始记录。无需立刻下载并上线完整素材。

## M1 · Web-only Fork（第一个功能里程碑）

- [ ] M1-01 简化 `game/package.json`：去 `build:app`、`ios`、`package`，移除确实不再引用的 Capacitor 依赖；同步 lockfile。
- [ ] M1-02 改 `game/src/ui/saves.ts`：只保留 IndexedDB 路径与自动/手动存档语义；补失败重试测试。
- [ ] M1-03 改 `game/src/ui/share.ts`：使用 `canvas.toBlob`、浏览器下载、Web Share API 可用时分享。
- [ ] M1-04 改 `game/src/ui/orientation.ts`：CSS 响应式为第一优先，支持的浏览器/全屏模式下尝试 Screen Orientation API，不依赖系统级锁定。
- [ ] M1-05 整理 `vite.config.ts`：以 Web 部署子路径 `/rich4/` 为可配置参数；删除针对 App file:// 的特殊假设。
- [ ] M1-06 校验 `index.html`、CSS、字体、DOM 动态资源地址是否服从 base URL；修复绝对 `/assets` 与 `/src` 的残留引用。
- [ ] M1-07 暂留原生平台目录供回退；在独立提交完成原生引用清除后再删除，不要第一天大规模删除。
- [ ] M1-08 确保无素材时错误提示清晰，不是无限黑屏；有合法素材时完成至少一张图的基本回合。
- [ ] M1-09 `npm test`、TypeScript、构建、PC+Android+iPad 浏览器最小回归。

**验收**：`dist/` 能由静态 HTTP(S) 服务部署；单机游戏不使用本地 Java/Node 后端处理规则；操作、存档、音频、UI 正常。该阶段不要求联机公网可用，也不要求 Canvas 已升级。

## M2 · Web 专用素材与加载策略

- [ ] M2-01 新增构建资源审计：按 `core/地图/地面风格/特效/音频` 分类统计压缩前后 bytes、文件数、清单引用数。
- [ ] M2-02 确定唯一资源引用关系：`maps.json`、`remake/index.json`、`orig/manifest.json`、`hd/manifest-hd.json`、`ground/index.json`；修复文件删除后清单引用未更新的问题。
- [ ] M2-03 保留 `bundle-assets.mjs` 的既有语义，新建 Web 专用输出模式（如 `--web`），不要破坏上游 App 模式的可比较基线。
- [ ] M2-04 实现资源分包：`shell`、`core`、`map:<id>`、`ground:<id>:<style>`、`optional`，以实际依赖图而非仅目录名称划分。
- [ ] M2-05 对缺文件/损坏清单产生构建失败或明确运行时可重试提示；所有资源具备长度/hash/version 元信息。
- [ ] M2-06 完成标题页关键资源优先加载、地图初始可见内容预取、同源 HTTP 缓存和重试策略。
- [ ] M2-07 验证 HD WebP 的精灵偏移、透明通道，检查 1×/2×/4× 精度档及内存预算。
- [ ] M2-08 在开发与测试环境测量首屏/首图流量及耗时，形成结果表。

**验收**：没有选择的地图不会在首屏被全部下载；所有资源引用校验通过；普通/大富豪/特殊地图不因资源分层退化；缓存更新不混版本。

## M3 · 测试站与首版发布

- [ ] M3-01 增加自动化检查：Vitest、TS、构建、资源清单校验、最小浏览器冒烟。
- [ ] M3-02 在授权允许条件下生成不可变版本目录，使用现有 VPS Nginx 的 `/rich4/` 入口提供静态服务。
- [ ] M3-03 验证 HTTPS、MIME、404、缓存控制、压缩和子路径 URL；不影响同域其他 `/apps` 项目。
- [ ] M3-04 测试回滚至上一版本，且历史存档不损坏。
- [ ] M3-05 在桌面 Chrome/Edge、Android Chrome、iPhone/iPad Safari 做回归；记录版本与真实设备。
- [ ] M3-06 统计初始加载、峰值传输、接口失败、客户端 FPS/长帧、存档恢复率。
- [ ] M3-07 形成首版测试报告并完成发布授权核对。

**验收**：固定版本、可回退、可复现；未获素材公开分发授权时此阶段只能在受控范围执行，不能将第三方游戏素材开放下载。

## M4 · PixiJS/WebGL 技术试验（非 M1/M3 必需）

- [ ] M4-01 抽离投影/摄像机/命中/遮挡排序的非 Canvas 逻辑。
- [ ] M4-02 抽象 `BoardRenderer`，保留原 Canvas 作为可切换实现。
- [ ] M4-03 用 PixiJS 8 实现**一张普通地图**的地面、人物、建筑、缩放与旋转。
- [ ] M4-04 解决大纹理分块、HD 图集、动态资源释放和 WebGL context lost/restored。
- [ ] M4-05 对照同设备同场景 1% low/平均帧率、p95 帧耗时、JS 堆、实际总内存、资源解码、加载量；不能仅看瞬时 FPS。
- [ ] M4-06 若收益不足、iOS 兼容回退困难、回归成本过高，则**停止迁移并保留 Canvas**。
- [ ] M4-07 若达到“可验证的明显改善且无玩法回归”，再扩展特殊地图、歌舞伎町、大富豪及特效。

**验收**：通过 [04-assets-and-performance.md](04-assets-and-performance.md) 所列性能试验门槛和 [07-acceptance-and-quality.md](07-acceptance-and-quality.md) 的跨平台用例，而非“代码已换 Pixi”即视为成功。

## M5 · 联机与存档生产化

- [ ] M5-01 将 PeerJS 信令地址、STUN/TURN 配置移出硬编码；公开客户端仅使用动态短期 TURN 凭据。
- [ ] M5-02 部署或托管可靠 PeerServer；保留网络诊断入口，验证 HTTPS/WSS 与跨 NAT。
- [ ] M5-03 房间协议增加 build/version 校验，避免不同版本规则锁步分叉；验证断线重连、房主迁移、超时托管。
- [ ] M5-04 保留 IndexedDB 7 个存档槽与自动保存语义；追加 JSON 导入/导出、schema 版本和迁移测试。
- [ ] M5-05 支持浏览器存储失效提示，绝不默默显示“已保存”；保持原有失败恢复链路。

**验收**：多设备跨网络联机回归、恶意或错误配置防护；存档可迁移并有备份/恢复方案。

## M6 · PWA、缓存与规模优化

- [ ] M6-01 App Shell PWA 清单、图标、基础缓存；不全量缓存所有地图和音效。
- [ ] M6-02 可选地图离线下载/删除、配额检测、缓存预算和失败反馈；Safari 真实设备验证。
- [ ] M6-03 评估 CDN/对象存储：当日志显示瓶颈为带宽、地域或高并发冷下载时再迁移。
- [ ] M6-04 建立安全、匿名的异常/性能监测策略，不收集游戏存档和聊天敏感内容。
- [ ] M6-05 每次上游同步后重复关键回归和公开素材许可核对。

## 每个阶段的“完成”定义

每阶段结束必须记录：合入的 commit/PR、测试环境、`npm test`/TS/构建结果、实际设备/浏览器、资源及性能度量、已知问题、回滚方案、剩余阻断项。缺任一关键证据时标记“进行中/受阻”，不能标记“已完成”。
